# 02. 파일빌더 site=3 작업목록

## 1. 목적

site=3(테스트홈페이지)에서, 현재 위젯빌더(configJson 방식)로 운영 중인 BO 화면들을 파일빌더로 하나씩 재구현하고 검증한다.

## 2. FO 콘솔에서 site=3으로 보는 방법

FO(localhost:3002)는 기본적으로 site=1 기준으로 동작한다. site=3 화면을 확인하려면 아래 두 방법 중 하나를 쓴다.

### 방법 A. 브라우저 콘솔에서 쿠키 설정 (재시작 불필요, 권장)

FO 페이지를 연 브라우저 콘솔(F12)에서 아래 명령어 실행:

```js
document.cookie = "ge_dev_site_id=3; path=/"
```

이후 새로고침하면 site=3 기준으로 데이터가 조회된다. 이 쿠키는 개발용으로 만들어진 오버라이드이며, 화면 어디에도 설정 UI는 없다.

### 방법 B. 환경변수 변경 (재시작 필요)

`fo/.env.local`의 `NEXT_PUBLIC_SITE_ID` 값을 `1`에서 `3`으로 변경한 뒤, fo 개발서버(포트 3002)를 재시작한다.

## 3. 공통 작업 프로세스 (메뉴 1개당 반복)

1. BO 위젯빌더(`/admin/templates/make/widget`)에서 **상세(등록/수정) 화면을 먼저** [파일빌드] 실행 → `bo/src/app/admin/generated/{상세slug}/page.tsx` 생성. 목록 산출물이 상세 경로를 `admin/generated/{상세slug}`로 하드코딩 참조하므로, 상세를 나중에 만들면 목록에서 링크가 깨진다.
2. 이어서 **목록 화면**을 [파일빌드] 실행 → `bo/src/app/admin/generated/{목록slug}/page.tsx` 생성
3. **목록·상세 산출물 둘 다** 상위 메뉴 카테고리 기준 폴더로 수동 이동한다 (예: press → `admin/generated/press-list/page.tsx` → `admin/company/press/page.tsx`, `admin/generated/press-basicInfo/page.tsx` → `admin/company/press/detail/page.tsx`). 상세는 `{카테고리}/detail` 하위 경로로 옮기는 걸 기본 규칙으로 한다.
4. 목록 파일 안에서 상세로 이동하는 부분은 `const GENERATED_PAGE_BASE = '/admin/generated';`라는 상수를 써서 `router.push(\`${GENERATED_PAGE_BASE}/{상세slug}\`)` 식으로 되어 있다. 이 상수는 파일빌드 코드 생성기(`widgetGenerator.ts`의 `GENERATED_PAGE_BASE_CONST`)가 항상 자동으로 박아넣는 값이라, 파일을 옮긴 뒤에는 **반드시 이 상수/참조를 새 상세 경로로 수동 수정**해야 한다 (안 고치면 URL이 계속 `/admin/generated/...`로 뜬다). 수정 시 이름도 `GENERATED_PAGE_BASE`(base+slug 조합용)가 아니라 `DETAIL_PAGE_PATH`(완전한 단일 경로)처럼 의미에 맞게 바꾸는 걸 권장한다 — 이렇게 하면 다음에 같은 화면을 파일빌드로 재생성해서 상수가 다시 덮어써지더라도 이름이 달라 눈에 바로 띈다.
5. BO 헤더에서 site=3(테스트홈페이지) 선택 → `/admin/settings/menus`에서 이동된 목록 경로로 메뉴 URL 등록
6. 브라우저에서 BO 등록 화면을 통해 데이터 10건 등록
7. 위 2번(FO site=3 전환 방법)으로 FO에서 반영 여부 확인

## 5. 진행 시 체크 사항

- 각 메뉴는 3번 프로세스를 순서대로 거친 뒤에만 다음 메뉴로 넘어간다.
- bo list, bo 상세는 각각 "개발완료"와 "검증완료"를 구분해서 기록한다 (개발이 끝났다고 검증완료는 아님). "검증완료"는 데이터 등록만이 아니라 목록의 검색/전체조회/미리보기, 수정(이동·데이터로드·저장), 삭제, 등록 필수값 검증까지 브라우저로 직접 눌러서 확인했을 때만 표기한다.
- fo는 브라우저에서 site=3 전환 후, BO에서 등록한 데이터 10건이 실제로 노출되는지 확인한 뒤에만 검증완료로 표기한다.
- 등록 화면 저장 버튼은 `window.confirm` 확인창을 띄운다. 자동화 도구로 등록할 때는 이 확인창을 처리할 방법이 있어야 하며, 없으면 저장이 막힌다.
- 등록 화면에서 제목을 입력한 직후 곧바로 다른 필드를 클릭하면 방금 입력한 제목 값이 반영되지 않는 경우가 있다. 제목을 입력한 뒤에는 값이 실제로 반영됐는지 확인하고 다음 필드로 넘어가야 한다.
