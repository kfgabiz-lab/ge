# 01. 파일빌더(File Builder) 현재 기능

## 1. 파일빌더란

파일빌더는 별도의 빌더가 아니라, **위젯 빌더 화면(`/admin/templates/make/widget`)의 [파일빌드] 버튼**을 가리킨다.

위젯 빌더에는 출구가 두 개 있다.

| 구분 | [저장] | [파일빌드] |
|---|---|---|
| 결과물 | DB `page_template.config_json` | 디스크에 실제 `.tsx` 소스 파일 |
| 렌더링 방식 | 런타임에 configJson을 해석해서 그림 (`/admin/widget/{slug}`, `/admin/widgetSub/{slug}`) | 평범한 React 컴포넌트로 그대로 렌더링 |
| 이후 수정 주체 | 운영자가 빌더 화면(UI)에서 수정 | 개발자가 코드 에디터에서 직접 수정 |

즉 [파일빌드]는 "빌더에서 조립한 화면을, 더 이상 빌더 설정이 아니라 진짜 소스 코드로 확정해서 넘겨받는" 기능이다.

## 2. 동작 흐름

[파일빌드] 버튼 클릭 1회 = API 2개가 순차 호출된다.

1. FE에서 `buildWidgetTsxFile()`이 위젯 설정을 tsx 문자열로 조립
2. `POST /api/v1/page-templates/generate` — 디스크에 파일을 쓴다 (DB 저장 없음)
3. `POST /api/v1/tsx-generation` — 생성 이력을 DB에 남긴다 (configJson + 생성된 tsx 코드)

## 3. 저장 경로 규칙

```
bo/src/app/admin/generated/{폴더명(slug)}/{파일명}.tsx
```

- 폴더명(slug)과 파일명은 파일빌드 실행 시 입력한 값이 그대로 쓰인다.
- 같은 경로에 다시 파일빌드하면 **덮어쓴다**.
- 권한: 시스템관리자 전용 (`@securityService.isSystemAdmin`)

⚠️ **`generated` 경로는 임시 산출 경로다.** 파일빌드는 항상 `bo/src/app/admin/generated/{slug}/`에 파일을 만들지만, 이 위치가 최종 운영 경로는 아니다. 실제 운영에 반영할 때는 화면이 속한 **상위 메뉴 카테고리 기준 폴더로 옮겨야 한다.** (예: blog는 목록 `generated/blog-list/page.tsx` → `admin/company/blog/page.tsx`, 상세 `generated/blog-basicInfo/page.tsx` → `admin/company/blog/detail/page.tsx`로 이동해서 운영 중.) **목록·상세 둘 다 옮긴다.** 이 이동은 자동화되어 있지 않고 개발자가 수동으로 옮긴다.

## 4. "하나씩 만드는 구조"

파일빌드는 폴더명 1개 + 파일명 1개를 받아 tsx 파일 1개를 생성한다. 여러 메뉴를 한 번에 일괄 생성하는 기능은 없다. 즉 위젯빌더로 만들어진 화면을 실제 파일로 확정하려면, 화면 단위로 하나씩 [파일빌드]를 실행해야 한다.

## 5. 지원 위젯 타입 및 블록별 지원 범위

위젯 타입은 전체 8종 중 **5종만 지원**한다. 미지원 타입은 화면에 경고를 띄우고, 생성된 코드에는 TODO 주석과 함께 빈 자리(placeholder)만 남는다.

| 위젯 타입 | 지원 여부 |
|---|---|
| search | 지원 |
| table | 지원 |
| space | 지원 |
| form | 지원 |
| multiselect | 지원 |
| category | 미지원 |
| sublist | 미지원 |
| tab | 미지원 |

### 블록별 세부 지원 범위

| 블록 | 지원 | 미지원 |
|---|---|---|
| search | 필드타입 input/select/date/dateRange/checkbox/radio/hidden, 화면형태 standard·simple, 공통코드 그룹, 조건부 숨김, 다국어 | 그 외 필드 타입 |
| table | 셀타입 text/badge/boolean/date/button/actions, 행 액션 edit·delete, 정렬·페이징·검색폼 연동 | 다른 화면과 연결되는 컬럼, 내부 이동 버튼 셀, 팝업으로 수정하는 방식 |
| space | textarea, 액션버튼(저장/닫기/팝업) | 경로이동, 엑셀, 별도저장, 외부 API 연동 방식 |
| form | input/select/date/radio/checkbox/textarea/에디터/이미지 | 그 외 필드 타입 |
| multiselect | 기본 옵션 조회 | 다른 화면 데이터를 참조해서 옵션을 구성하는 방식 |

## 6. 메뉴 등록은 자동화되어 있지 않다

파일빌드는 파일만 만들 뿐, **메뉴에 자동으로 연결해주지 않는다.** 메뉴 등록은 다음 절차로 수동으로 진행한다.

1. BO 상단 헤더에서 대상 사이트 선택 (site를 바꾸면 이후 모든 요청에 해당 site 기준으로 처리됨)
2. `/admin/settings/menus` (메뉴관리) 이동
3. 트리에서 상위 메뉴 선택 후 하위 메뉴 추가
4. 메뉴 이름/URL 입력 — 파일빌드 산출물은 템플릿 선택 목록에 뜨지 않으므로, URL을 직접 타이핑해야 한다 (예: `/admin/company/blog`)
5. 저장 (시스템관리자 또는 최고관리자 권한 필요)
6. 필요 시 역할별 메뉴 권한, API 권한 매핑 추가

메뉴는 사이트별로 구분되어 노출된다. 특정 site로 만든 메뉴는 해당 site를 선택했을 때만 화면에 보인다.

## 7. 현재 파일빌드로 만들어진 화면 (blog 예시)

blog는 리스트 화면과 등록/수정 화면 두 개로 구성되어 있고, 둘 다 파일빌드로 생성이 완료된 상태다.

### blog-list (목록 화면)
- 검색폼(조건 3개, simple 형태) + 조건에 맞는 목록 조회
- 정렬, 페이징, 총 건수 표시
- 행 클릭 시 수정 화면 이동
- 행 삭제 (확인창 후 삭제 API 호출)
- FO 미리보기 팝업 (미리보기 토큰 발급 후 새 창으로 FO 상세 페이지 오픈)
- 신규 등록 버튼 (등록 화면으로 이동)

### blog-basicInfo (등록/수정 화면)
- 입력폼 2개 + 다중선택 1개로 구성
- 값 변경/포커스아웃 시 검증, 조건에 따른 필드 표시/숨김, 값 자동생성
- 파일 업로드/다운로드/삭제, 이미지 크기·용량 제한 검증
- 저장 시 필수값 검증 → 파일 업로드 → 저장 API 호출 (신규/수정 자동 판별)
- 화면 이탈 시 저장 여부 확인, 다국어 지원
